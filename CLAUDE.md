## Project

**Kotihommat** — mobile-first family chore & allowance management app. Two roles: **vanhempi** (parent, manages chores/family/payments) and **lapsi** (child, marks chores done, tracks balance). Stack: **React + Vite + TypeScript + Firebase** (Auth, Firestore, Cloud Functions).

## Design references (not production code)

- `Kotihommat.dc.html` — interactive prototype. Open directly in a browser to click through every screen and state. **Single source of truth for exact Finnish copy, spacing and interaction states.**
- `styles.css` — the "Classical" design system, source of truth for all tokens and component classes. Port these class names 1:1 into the React app (CSS Modules or styled-components are fine, but preserve the same class semantics).

## Architecture decisions

### Role-based accent system
The entire visual identity swaps via 9 CSS custom properties at the `:root`. Parent = gold ramp (`--color-accent: #b68235`). Child = cool blue ramp (`--color-accent: oklch(58% 0.11 220)`). All components (`.btn-primary`, `.tag-accent`, focus rings) read `--color-accent*` unmodified — only the variables change. Swap all 9 `--color-accent*` properties together on a wrapper element when role = lapsi.

### Firebase data model
```
families/{familyId}
  /members/{uid}          role, firstName, username (child only)
  /chores/{choreId}       name, priceCents (50-cent steps), type, assignedMemberIds[], active
  /weeklyPlans/{weekId}
    /assignments/{choreId}  { ma..su: memberId } for daily, { all: memberId } for weekly
  /taskInstances/{id}     choreId, memberId, date (ISO, Europe/Helsinki), isoWeek, priceCents, status, completedAt
  /members/{childId}
    /absences/{id}        type (loma|sairas), from, to
    /payments/{id}        amount (cents), date  →  also update denormalized paidTotal on member doc
```

### taskInstance generation
`taskInstances` are **generated by a scheduled Cloud Function** from `chores` + `weeklyPlans` — never written directly by the client. The client only writes `status` on existing instances (lapsi toggling tehty/tekematon).

### Child account creation
Use **Admin SDK in a Cloud Function** to create child accounts — never `createUserWithEmailAndPassword` on the client, which would break the signed-in parent's session. Children have no email; use a fixed internal domain behind the scenes.

### Task status machine
`tekematon → tehty → merkitty` (merkitty = paid/processed). No parent approval step — child's mark is final.

## App shell

Mobile-first, `min(480px, 100vw)` wide, `100dvh` tall. Sticky header (`.nav`) + sticky bottom tab bar (3 tabs, differ by role) + scrollable content area. No transitions beyond 150ms CSS on toggles/inputs.

## Screens

**Lapsi (3 tabs):** Tänään (today's tasks, dismissible banner for undone tasks) · Viikko (full ISO week, read-only) · Oma saldo (piggy bank visual, earned/paid/pending stats)

**Vanhempi (3 tabs):** Kotityöt (Lista / Viikkosuunnittelu segmented) · Perhe (member list, add child, invite parent via expiring Firestore token) · Lapsen profiili (7-day mini-calendar, stats, absences, payment history, Merkitse poissaolo / Merkitse maksetuksi)

**Kaikki:** Asetukset-dialog (tumma tila toggle, push-ilmoitukset placeholder "Tulossa pian", päivittäinen muistutusaika select)

## Firebase security rules pattern

- `parent`: read/write all data in own family
- `child`: read own family data, write only `status` on own `taskInstances`

## v1 scope limits

- No parent approval for completed chores
- No push notifications (FCM) — show in-app banner only; settings toggle shows "Tulossa pian"
- No age field or personal data beyond first name
- No automatic pay cycle — parent uses manual "Merkitse maksetuksi"
- Payments cap at outstanding balance (`earnedTotal - paidTotal`); `paidTotal` is denormalized on the member doc
